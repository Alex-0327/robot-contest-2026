# 比赛当天现场 SOP（10-12 赛场调试后定稿）

给比赛当天现场操作的人看，不需要懂代码，按顺序照做即可。
踩坑与事故预防见根目录 `操作注意事项.md`，开机激活细节见根目录 `SOP.md`。

> **10-14 布局更新**：官方公布笔筒/砚台固定位置（从机器人对面看：笔筒距桌左缘
> 27.5cm、距下缘 7.5cm；砚台距左缘 45cm、距下缘 4.5cm）——两者相邻（约 17.5cm），
> 都在远离基座一侧，且筒内竖着的毛笔顶部高过砚台悬停位。**笔筒区只从正上方垂直
> 进出**：横向进出笔筒区前先抬到高过筒内笔顶的高度（面板内建 340mm 下限），
> 低位横移必撞筒内笔。旧的高空走廊变成可选（实测直飞不剐蹭就不示教走廊点）。

## 〇、现场机环境速查

- 现场机是 Linux 电脑，远程登录：`ssh dex@<现场机IP>`
- 仓库目录：`~/robot-contest-2026`
- Python 解释器：`~/miniconda3/envs/robot/bin/python`
- 跑任何控制脚本前都要带 SDK 路径，完整命令模板：

  ```bash
  cd ~/robot-contest-2026
  PYTHONPATH=~/fairino-python-sdk/linux/fairino ~/miniconda3/envs/robot/bin/python src/某脚本.py
  ```

- 航点微调面板：`localhost:8080`（由 `src/jog_server.py` 提供，见第二节）
- **设备断电前的规矩：机械臂先回 `home` 航点、灵巧手张开，再断电**

## 一、开机自检（错了后面全白搭）

1. **检查接线**（全部断电状态下）：
   - 手指轻拽灵巧手 CANFD 端子，确认不松（虚接 = 手完全无响应）
   - 电脑 ↔ 控制柜网线插紧
   - **急停按钮确认是旋出状态**（按下去 = 控制柜闪一下就灭）
2. **控制柜上电** → 灯环变色循环 = 自检中（1~2 分钟）→ **绿色常亮 = 就绪**。
   没绿灯常亮之前不要做任何操作
3. **灵巧手上电**（能听到掌内风扇声 = 已供电，此手无指示灯，属正常）
4. **开 Linux 电脑**，跑链路自检：

   ```bash
   cd ~/robot-contest-2026
   PYTHONPATH=~/fairino-python-sdk/linux/fairino ~/miniconda3/envs/robot/bin/python src/check_all.py
   ```

   看到臂位姿 + 手关节反馈、无错误码 = 链路全通。报错先看「八、应急处理」。

5. **脚本切换规矩**：控制器（CNDE 状态流）同一时刻只认一个客户端。
   **每换跑一个 Python 脚本，先杀干净残留进程**：

   ```bash
   pkill -f 'python.*src/' ; sleep 12
   ```

   残留进程不杀，新脚本会报状态流相关错误，等 12 秒是等控制器释放旧连接。

## 二、六点标定（纸阵）——每次换纸/动纸后必做

**开场第一件事：重标 home。** 旧 home 是「臂伸到桌面上方 z≈196 的低位」，
存在关节角里、与基座摆放无关——重新装机后这个构型可能正对着纸张/笔筒/砚台，
直接点「回 home」或跑任何流程都会撞。所以**出厂航点文件里 home 已被清空**——
流程按钮在重标前是灰的，点不动。到场后先别点任何流程：用第 6 步微调/飞到坐标
把臂摆到 **x≈0 的高位收拢姿态**（不罩在桌面任何东西上方），然后点向导第 1 行
home 的「保存到该点」。**home 标好之前，第 2/4 步的流程按钮会一直保持灰色。**

标定要存 6 个航点（写在 `src/waypoints.json` 里）：

| 航点名 | 是什么 |
|---|---|
| `paper1_tl` / `paper1_tr` / `paper1_bl` / `paper1_br` | 纸阵四个角 |
| `paper1_cell00_tl` | 第 0 格十字中心（笔尖对十字交点） |
| `paper1_cell00_corner_tr` | 第 0 格右上角 |

**br（右下角）机械臂限位到不了，不要硬去**：用另外三个角按矩形三角合成推算，
程序会算，不用人到现场点。

操作步骤：

1. 先备份再动手：`cp src/waypoints.json src/waypoints.json.bak`
2. 启动微调面板（先确认没有其他脚本占着臂，见第一节第 5 条）：

   ```bash
   PYTHONPATH=~/fairino-python-sdk/linux/fairino ~/miniconda3/envs/robot/bin/python src/jog_server.py
   ```

   浏览器打开 `http://localhost:8080`（从别的电脑访问需 SSH 转发：
   `ssh -L 8080:127.0.0.1:8080 dex@<现场机IP>`）
3. 面板第 3 步「航点标定向导」按顺序逐行点「去微调」（顺序：home → 砚台上方 →
   蘸墨点 → 笔筒上方 → 抓笔位 → 画龙点睛点 → 纸面 6 点；去笔筒区时面板自动抬到
   高位越过筒内笔顶再横移），到位后用第 6 步微调对准
   （先 5mm 粗调、接近切 1mm 精调，姿态歪了用 RX/RY/RZ）。
   **全程统一写字姿态（rz≈-120°），只动 xyz**
4. 对准后点「保存到该点」——面板自动连读 3 次确认臂停稳（晃动 ≥1mm 不让存）、
   写盘后回读核对，看到「✓已保存并核对」才算完成

**首次标定 pen_lift / pen_grasp（航点还不存在，「去微调」是灰的）怎么过去：**

1. 空手、手伸直。在面板顶部读出 home 位姿的 x、y
2. 目测/尺量笔筒相对基座的方向和距离，估算笔筒正上方的 x、y（差 10cm 也没关系）
3. 第 6 步「飞到坐标」：填估算的 x、y，悬停 Z 填 **250 以上**（筒里笔很高），
   确认后臂会抬到 300 平移过去——**一次性直飞，不要用微调一点一点挪**
   （点动逼近限位会锁死构型分支，10-12 标 br 时遇到过；直飞是重新解算不会）
4. 到位后 RZ 把腕部转回 rz≈-120°、RX/RY 调平笔尖朝下，再 XY 对准笔筒正上方、
   Z 降到悬停高度，存 pen_lift
5. pen_grasp 同理：存完 pen_lift 后它的「去微调」就亮了，自动抬 340 过去，
   再 Z− 降到抓笔高度存点
6. 备选：第 6 步微调真挪不动时，用 WebApp **关节空间**点动粗移（绝不拖腕），
   再回面板修姿态。不要用手掰臂（拖动示教会把写字姿态带乱）
5. **存完必须落盘验证**：`cat src/waypoints.json`，把刚存的点和上一点的数值
   比对——同一阵列相邻点只差几十 mm，**差出 10cm 级就是脏数据**
   （10-12 真出过：误操作存出偏 14cm 的点，幸亏比对发现了）
6. 6 个点全部存完、比对无误后，**git commit**（waypoints.json 是标定成果本体，
   丢了要重标一下午）
7. Ctrl+C 关面板，`pkill` 干净再等 12 秒，才准跑下一个脚本

## 三、握笔后触纸验证（30 秒，能定位大半"写不出来"问题）

握笔完成后、正式写之前必做：

1. 面板上让臂回左上角航点（`paper1_tl` 一带），Z 向 1mm 步长降到写字高度
2. **看笔尖是否刚好碰到纸面**：
   - 刚好碰纸 → z 参数有效，可以写
   - 碰不到 / 压得太狠 → **握笔深度变了**。所有 z 参数（PRESS_MM、ink_dip 等）
     都基于当前握笔深度，深度变了 z 全偏 → 重新握笔，重新验证

**每次重新握笔（包括彩排中调笔后），都要重做这一步。**

## 四、完整流程彩排一次

正式写之前完整彩排一遍（可用 `src/demo_cycle.py`，或按下面人工确认每步）：

1. 拿笔
2. 到左上角停 **5 秒**——人对一遍笔尖和纸的位置（对纸）
3. 放回笔筒、**松手等 5 秒**——让笔在筒里自然归位（调笔）
4. 重新握紧 → **重做第三节触纸验证**
5. 蘸墨 → 写字 → 还笔 → 归位

每步之间看控制器有没有报警，有报警先复位再查因，不要带病往下走。
彩排没问题 → 等诗题公布；**不要手痒改航点**。

## 五、诗题公布后：查字库 → 正式执行

### 5.1 检查缺字（毫秒级，先做这个）

笔画数据来自 hanzi-writer-data@2.0.1，本地缓存在 `data/strokes_cache.json`
（已预抓唐诗三百首 2516 字）。诗题一公布：

```bash
PYTHONPATH=~/fairino-python-sdk/linux/fairino ~/miniconda3/envs/robot/bin/python src/stroke_lib.py --offline 诗文内容
```

- 全部命中缓存 → 直接进 5.2
- **有缺字** → 两条路：① 现场有网就连网抓
  （去掉 `--offline` 或加 `--fetch 诗文`）；② 没网就**换备选诗**，别硬写
- 复杂字（笔画多的合体字）默认被白名单拦下，这是防止坏字形上纸的保险。
  确认字形没问题后用 `--allow-complex` 放行
- 解析和规划都是毫秒级，**时间全花在书写上：约 20 秒/字，预算按 300 秒/10 字**

### 5.2 正式执行

```bash
cd ~/robot-contest-2026
PYTHONPATH=~/fairino-python-sdk/linux/fairino ~/miniconda3/envs/robot/bin/python \
  src/write_engine.py --char 诗文 --row 1 --col 1 --allow-complex --dip --execute
```

- `--char` 后跟诗文内容；`--row/--col` 是起始格
- `--dip` = 写字前先蘸墨一次；`--execute` = 真机执行（不加只出方案不动臂）
- 真机模式会要求输入 `y` 确认，确认前最后检查：手握稳笔、笔尖朝下、臂周清空、
  人手放急停旁

## 六、关键参数备查（写在 src/write_engine.py / waypoints.json 里，一般不要动）

| 参数 | 值 | 含义 |
|---|---|---|
| `PRESS_MM` | 10 | 落笔下压量（往纸里压 10mm） |
| `CENTER00_CORR_MM` | (10.0, -8.0) | 锚点修正（人眼点的十字中心常偏几 mm） |
| `GLYPH_SCALE` | 0.95 | 字形缩放（防满格大字遇锚点误差出格） |
| `ROW_PITCH_CORR_MM` | -2.0 | 行距修正 |
| 蘸墨 `ink_dip` | 现场标定 | 笔尖触墨面高度（z=187 是 10-12 旧值，新布局重标） |
| 写字姿态 | rz≈-120° | rz 扫描全纸可达性最优 |
| 高空走廊 | `ink_corridor_1/2` | 可选（10-14 新布局）：砚台↔纸直飞实测剐蹭才示教 |

改任何一个参数前先问程序组，改完 git commit。

## 七、断电顺序（收工 / 中午离场）

1. 确认所有运动脚本已跑完、面板已关（Ctrl+C + pkill）
2. **机械臂回 `home` 航点、灵巧手张开**
3. 关控制柜电源（臂有关节抱闸，断电自锁不会塌）
4. 关灵巧手供电
5. 关电脑

## 八、应急处理

### 碰撞停机（err=186 = 运动中碰撞停止）

1. 先确认臂和周围东西都没坏，把臂周围清空
2. 面板上点「**复位+自动模式**」（碰撞后控制器锁存停止态，不复位的话后续
   运动指令会沉默失败——返回成功但臂不动）
3. 复位后还动不了 → **重启控制柜**（断电等 10 秒再上电，等绿灯）。
   重启后必查三件事：
   - 激活的工具坐标系会重置回 0 → 在 WebApp 上改回 1 号工具（或告知程序组）
   - CNDE 状态流要等几秒才起来
   - 重跑 `check_all.py` 确认链路全通，再继续

### 强杀进程后连不上（CNDE 占用）

控制器的状态流只支持单连接，且释放有约 12 秒延迟。
**Ctrl+C 或 kill 掉任何连着臂的 Python 进程后，先 pkill 干净、等 12 秒以上再启动
新程序**，否则会报状态流相关错误。等完还连不上 → 重启控制柜。

### 错误码速查

| 错误码 | 含义 | 处理 |
|---|---|---|
| err=14 | 有未复位报警 | 先复位，别排查别的 |
| err=99/112 | 经过奇异点 | 已内建 move_ik 规避；仍出现就换条路 |
| err=123 | 关拖动后立刻切模式 | 等 1 秒重试 |
| err=154 | 工具坐标系不符 | 控制柜上改回 1 号工具 |
| err=185 | 超工作空间 | 目标点太远，检查航点数值 |
| err=186 | 运动中碰撞停止 | 见上面「碰撞停机」 |

### 其他常见现象

| 现象 | 原因 | 处理 |
|---|---|---|
| 控制柜闪灯即灭 | 急停被按下 | 旋出急停，重新上电 |
| 手完全无响应 | CANFD 端子虚接 | 断电后重新压紧端子 |
| 网页打不开 | 面板没启动 / SSH 转发断了 | 回现场机看面板进程，重连 SSH |
| 新脚本报状态流错误 | 上一个脚本没杀干净 | pkill + 等 12 秒，见第一节第 5 条 |
| 写字有动作没落墨（空写） | 握笔深度变了 | 见操作注意事项「笔滑事故链」 |
| 去航点报错「逆解失败」 | 航点不可达（臂被挪动过？） | 先拍照记录，通知程序组，不要硬试 |
